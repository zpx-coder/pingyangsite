## 1. 需求概述

### 1.1 需求背景

平阳县定期举办**外贸对接会**，组织本地产业带企业与海外采购商面对面洽谈。
v1.0 官网已具备产业宣传与询盘转化能力，v1.1 在官网新增外贸对接会专题页面与
报名通道，在管理后台新增报名信息汇总管理，将会务宣传、报名收集、数据运营
打通到现有平台内。

### 1.2 需求目标

1. 官网顶部导航新增「外贸对接会」入口（位于「特色产业」菜单右侧），点击
   跳转对接会专题页；
2. 新增外贸对接会专题页，通过图文内容全面介绍平阳外贸对接会（中/英双语）；
3. 专题页提供会议报名：弹窗填写姓名、手机号、邮箱、出发城市、意向采购产品
   后提交；
4. 管理后台新增「对接会报名管理」列表，汇总统计官网提交的报名信息。

### 1.3 本期范围（In Scope / Out of Scope）

**In Scope**

- 官网：顶部导航新增菜单项；对接会专题页（图文，后台可配置）；报名弹窗与
  提交链路；
- 后台：报名管理模块（统计汇总、列表、详情、状态标记、导出）；
- 数据：报名表 + 对接会页面内容配置；公开/管理接口；双语与 SEO 配套。

**Out of Scope**

- 报名在线支付、电子门票/签到二维码；
- 用户侧报名修改与取消、报名审核流（多级审批）；
- 短信/邮件自动通知（报名成功仅页面弹窗提示；人工外呼/邮件跟进）；
- 会议议程、嘉宾、展商的多页管理（一期以单页图文承载）；
- 报名信息与具体产品/企业的关联（对接会报名为会议级，不挂产品快照，见决策项 D-5）；
- 移动端独立版本（沿用 v1.0 基本响应式适配约定）。

## 2. 官网功能需求

### 2.1 顶部导航新增「外贸对接会」（#/matchmaking）

| 项 | 说明 |
| --- | --- |
| 位置 | 「特色产业」菜单右侧、「新闻动态」左侧；导航顺序变为：首页 / 关于平阳 / 特色产业 / **外贸对接会** / 新闻动态 / 联系我们 |
| 交互 | 普通可点击链接（非「特色产业」的悬停下拉式），点击跳转 `/zh-CN/matchmaking`（英文态 `/en/matchmaking`） |
| 高亮 | 当前页高亮规则与既有菜单一致（/matchmaking 下高亮「外贸对接会」） |
| 双语 | zh「外贸对接会」；en「Trade Matchmaking」 |

### 2.2 外贸对接会专题页（#/matchmaking）

**页面定位**：对外贸对接会的专题宣传页，图文介绍 + 报名转化入口。

| 模块 | 内容 | 说明 |
| --- | --- | --- |
| 页面横幅 | 横幅配图（后台可配置）+ 页面标题 | 复用官网 page-banner 视觉（类目详情页同款：配图 + 深青渐变遮罩） |
| 图文介绍区 | 富文本图文内容（中/英），全面介绍对接会（背景、规模、产业、往届情况等） | 后台「页面内容管理」配置，双语自动翻译 + 人工校对（沿用 v1.0 §5.2） |
| 报名入口 | 页面内「立即报名」按钮（横幅区与文末各一处），点击弹出报名弹窗 | 按钮文案双语 |

**内容管理方式（建议）**：沿用 v1.0 页面内容管理模块，新增配置项
`matchmaking_page`——横幅图 + 标题（中/英）+ 富文本正文（中/英）。配置保存后
官网即时生效（ISR ≤ 60s 重验证），与 about/contact 配置模式一致。

**SEO**：页面独立 TDK（中/英）、hreflang 标注、sitemap.xml 增项、图片 alt
必填（沿用 v1.0 §9.3）。

### 2.3 报名弹窗与提交

**触发**：点击页面「立即报名」按钮弹出（复用官网既有弹窗组件视觉）。

**报名表单字段**

| 字段 | 必填 | 校验规则 |
| --- | --- | --- |
| 姓名 | 是 | 2–50 字符 |
| 手机号 | 是 | 6–20 位数字（含 + 号、空格、-） |
| 邮箱 | 是 | 邮箱格式 |
| 出发城市 | 是 | 2–50 字符（建议） |
| 意向采购产品 | 是 | 10–500 字符，占位提示「如：宠物玩具、编织袋、汽摩配件…」（建议） |
| 图形验证码 | 是 | 不区分大小写；验证失败刷新（沿用询盘验证码机制） |

**关键规则**

- 提交需通过验证码校验与频率限制（同 IP 1 分钟内 ≤ 3 次、每日总量上限，
  沿用询盘防刷机制）；
- 提交成功后弹窗确认（「报名成功，我们将在 1–2 个工作日内与您联系确认参会
  信息」），可关闭继续浏览；防重复提交（前端禁用按钮 + 后端幂等）；
- 后台按提交时间落库，记录来源语言（lang）与提交 IP（用于限流与追溯）；
- 报名不关联具体产品/企业（会议级报名，见决策项 D-5）；
- 全部字段服务端二次校验（不信任前端校验，沿用 v1.0 §9.2）。

## 3. 管理后台功能需求

### 3.1 侧栏导航

侧栏新增菜单项「对接会报名」（建议置于「询盘管理」之后），进入报名管理页。

### 3.2 对接会报名管理（#/admin/matchmaking）

| 模块 | 说明 |
| --- | --- |
| 统计汇总 | 顶部统计卡片：报名总数、今日新增、本周新增、待处理数（统计口径与询盘管理一致） |
| 列表 | 筛选：状态、关键词（姓名/手机号/邮箱）、提交时间范围；分页每页 20 条 |
| 表格列 | 提交时间、姓名、手机号、邮箱、出发城市、意向采购产品摘要、来源语言、状态、操作 |
| 详情弹窗 | 查看报名完整字段（意向采购产品全文） |
| 状态处理 | 「标记已联系」/「标记待处理」（建议），可批量处理 |
| 导出 | 导出当前筛选结果为 Excel（.xlsx），字段与表格列一致（沿用询盘导出实现） |

**关键规则**

- 报名记录自官网提交后 1 分钟内可在后台列表可见（验收以 ≤ 5 分钟为准，
  沿用询盘同步实现）；
- 后台仅查看与状态标记，不提供站内回复（人工电话/邮件跟进）；
- 报名记录不提供编辑（用户填报信息为原始凭证）；提供删除需二次确认
  （沿用询盘管理交互）。

## 4. 数据模型（v1.0 增量）

### 4.1 实体关系增补

```
Product 1 ──── N Inquiry          （v1.0 已有）
新增：MatchmakingRegistration（独立实体，无外键关联）
PageContent 新增 key：matchmaking_page
```

### 4.2 表结构

```sql
-- 对接会报名（独立实体，无产品/企业关联）
matchmaking_registrations(id, name, phone, email, departure_city,
                          intended_products, lang, status, ip,
                          created_at)
-- status: 0 待处理 / 1 已联系
-- lang: zh-CN / en（来源语言，与 inquiries.lang 口径一致）
-- ip: 提交 IP（限流追溯，不入日志明文输出）

-- 页面内容（v1.0 page_contents 表新增一行配置，无表结构变更）
page_contents(key = 'matchmaking_page', config(text), updated_at)
```

> 沿用 v1.0 已确认约定：MySQL 5.6.16 无原生 JSON 类型，config 以 text 列
> 存储、应用层序列化；字符集 utf8mb4。

## 5. 接口契约

统一信封 `{code, message, data}`（0=成功），沿用既有前缀与鉴权方式。

| # | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 1 | POST | `/api/v1/public/matchmaking/registrations` | 报名提交：字段校验 + 验证码校验 + IP 限流 + 幂等；落库 lang/ip |
| 2 | GET | `/api/v1/public/matchmaking/page` | 对接会页面内容（banner + 标题 + 富文本，双语），官网 SSR/ISR 使用 |
| 3 | GET | `/api/v1/admin/matchmaking/registrations` | 分页列表 + 筛选（status/关键词/时间范围）+ 统计卡片数据（或独立 stats 字段） |
| 4 | GET | `/api/v1/admin/matchmaking/registrations/:id` | 报名详情 |
| 5 | PATCH | `/api/v1/admin/matchmaking/registrations/:id/status` | 状态标记（含批量） |
| 6 | GET | `/api/v1/admin/matchmaking/registrations/export` | 导出当前筛选结果 Excel |

验证码、限流、会话鉴权、信封规范均沿用 v1.0 既有实现（询盘链路同构）。

## 6. 非功能需求（增量）

以下为 v1.1 增量要点，其余（性能、安全、SEO、兼容性、合规、数据运维）全部
沿用 v1.0 PRD 第 9 章：

- **性能**：报名提交接口响应 ≤ 3s，防重复提交；对接会页 LCP ≤ 2.5s（首屏仅
  加载横幅图）；
- **安全**：报名表单图形验证码 + IP 频率限制 + 每日总量上限（与询盘同规则）；
  手机号/邮箱在后台完整展示但日志中脱敏；
- **SEO**：/matchmaking 独立 TDK、hreflang、sitemap 增项；
- **合规**：报名涉及个人信息收集，合规口径与询盘一致（上线前评估补充合规
  文案，沿用 v1.0 §9.5 提示）；
- **E2E 回归**：全量 E2E 在 v1.0 的 15 场景基础上新增报名链路场景（官网报名
  提交 → 后台可见；报名限流），总场景数仍 ≤ 20 上限。

## 7. 验收标准

**官网**

- [ ] 导航「外贸对接会」位于「特色产业」右侧，zh/en 双语文案正确，点击跳转
      对应语言页面，当前页高亮正确；
- [ ] 对接会页横幅、标题、图文内容与后台配置一致；中/英内容随语言切换，无
      残留；ISR 60s 内配置生效；
- [ ] 报名弹窗字段齐全（姓名/手机号/邮箱/出发城市/意向采购产品/验证码），
      校验规则生效（非法输入拦截 + 错误提示）；
- [ ] 验证码错误被拒、同 IP 1 分钟第 4 次提交被限流提示、重复提交被拦截；
- [ ] 提交成功弹窗文案正确，提交后 5 分钟内在后台可见；来源语言记录正确；
- [ ] 对接会页 TDK、hreflang、sitemap 正确；无中文残留（英文态）。

**后台**

- [ ] 侧栏「对接会报名」入口正常；列表、筛选、分页、详情弹窗正确；
- [ ] 统计卡片数字与列表一致（总数/今日新增/本周新增/待处理）；
- [ ] 状态标记（单个/批量）生效；Excel 导出字段完整；
- [ ] 后台登录态、权限拦截与既有模块一致（未登录访问重定向登录）。

**回归**

- [ ] v1.0 全部既有功能无回归（官网 15 场景 E2E 全绿 + 新增报名场景）；
- [ ] 双语文案键位无冲突，i18n 字典新增键全部落地。

## 8. 待确认决策项（请负责人评审）

| # | 决策项 | 建议 | 影响 |
| --- | --- | --- | --- |
| D-1 | 报名弹窗字段必填性 | **全部 5 项必填**（出发城市与意向采购产品为会务筹备所需） | 若部分选填，仅调整前端校验与后端校验规则 |
