## 1. 部署架构与域名规划

```
用户（全球）
   │  HTTPS 443
   ▼
┌─ ECS ────────────────────────────────────────────────┐
│  Nginx（80 → 443 跳转；TLS 终结）                     │
│   ├─ /            → 127.0.0.1:3000  官网 Next.js(PM2) │
│   ├─ /admin/      → 静态文件        后台 Vue SPA(dist) │
│   ├─ /api/v1/*    → 127.0.0.1:3001  API NestJS(PM2)   │
│   └─ /img 等静态    → 官网 public 目录（由 Next 服务）   │
│  API ── Redis（本机 127.0.0.1:6379，验证码/限流/会话）  │
│  API ── RDS MySQL（内网）── OSS（上传图片，公共读）     │
└──────────────────────────────────────────────────────┘
```

| 域名/路径 | 指向 |
| --- | --- |
| `https://www.<域名>/` | 官网（默认语言 zh-CN；`/en` 英文态） |
| `https://www.<域名>/admin/` | 管理后台（同域，登录会话 Cookie 同源） |
| `https://www.<域名>/api/v1/...` | 后端接口（同域反代，后台/官网前端相对路径直连） |
| `https://www.<域名>/uploads/...` | 仅本地存储驱动使用；生产走 OSS，无需配置 |

端口规划（仅 ECS 内网可达，安全组不对外暴露 3000/3001/6379/3306）：

| 端口 | 服务 |
| --- | --- |
| 80 / 443 | Nginx（对外唯一入口） |
| 3000 | 官网 `next start`（PM2） |
| 3001 | API `node dist/main.js`（PM2） |
| 6379 | Redis（仅绑定 127.0.0.1） |

## 2. 云资源准备

### 2.1 ECS

1. 规格：起步 **2C4G**（官网构建期内存峰值较高，见 §5.4 说明）；系统盘 ≥ 40G。
2. 操作系统：Ubuntu 22.04 / Alibaba Cloud Linux 3 均可。
3. **安全组规则**（白名单收敛）：

   | 方向 | 端口 | 来源 |
   | --- | --- | --- |
   | 入 | 22 | 公司出口 IP（按需临时开放） |
   | 入 | 80 / 443 | 0.0.0.0/0 |
   | 入 | 其余全部 | 拒绝 |

4. 安装基础环境（Node 20 LTS + pm2 + git + nginx）：

```bash
# Node 20（以 nvm 或 NodeSource 安装；生产版本与开发一致：Node 20.x）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs
node -v   # 应为 v20.x

sudo npm i -g pm2
sudo apt-get install -y git nginx
```

5. Redis 7（本机容器或 apt 安装；**仅绑定 127.0.0.1，不设密码**——当前代码未接入密码变量，见附录 B）：

```bash
sudo apt-get install -y redis-server
# 确认配置：/etc/redis/redis.conf 中 bind 127.0.0.1、protected-mode yes、port 6379
sudo systemctl enable --now redis-server
redis-cli ping   # PONG
```

### 2.2 RDS MySQL

1. 创建 RDS MySQL 实例，版本建议 **8.0**（本地联调用 5.6.16，数据模型已预留
   5.7/8.0 升级兼容，见开发计划风险表 #8；上架后按 §7 冒烟全流程验证）。
2. **白名单**：仅添加 ECS 内网 IP（RDS 不对公网开放）。
3. 创建数据库与账号（utf8mb4 字符集）：

```sql
CREATE DATABASE pingyangsite CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'pingyang'@'%' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON pingyangsite.* TO 'pingyang'@'%';
FLUSH PRIVILEGES;
```

### 2.3 OSS

1. 创建 Bucket（地域任意，建议与 ECS 同地域走内网上传）。
2. **读写权限设为「公共读」**：产品图、企业图、横幅图入库后由浏览器直接
   加载（OSS 驱动公开地址 = `https://<bucket>.oss-<region>.aliyuncs.com/<key>`，
   见 `services/api/src/storage/oss.driver.ts`）。
3. 创建 **RAM 子账号**并仅授权最小权限，用子账号 AccessKey 部署（勿用主账号）：

   - OSS：指定 Bucket 的 `oss:PutObject`、`oss:DeleteObject`、`oss:GetObject`；
   - 机器翻译：`alimt:TranslateGeneral`（API 名称以控制台为准）。
4. 可选：开通 CDN 并绑定加速域名（`OSS_CDN_DOMAIN`），公开地址自动切换为 CDN。

### 2.4 域名与 HTTPS

1. 已备案域名添加 A 记录 → ECS 公网 IP（`www` 与根域按需）。
2. 在阿里云证书服务申请**免费 DV 证书**（或上传公司已有证书），签发后下载
   Nginx 格式（pem + key），上传到 ECS `/etc/nginx/ssl/`。
3. 证书有效期到期前续签（免费证书 3 个月一换；如用 certbot 可自动续期）。

### 3.1 拉取代码

cd /opt/app

### 3.2 安装依赖（三处）

```bash
cd /opt/app/pingyangsite
npm ci --prefix services/api

npm ci --prefix frontend/admin
```

### 3.3 环境变量（三处文件，全部只在服务器上创建，**禁止提交仓库**）

**① `services/api/.env`**（Prisma 与种子读取；复制自 `.env.example` 改真实值）：

```bash
# 生产数据库连接串（RDS 内网地址）
DATABASE_URL="mysql://pingyang:<密码>@<RDS内网地址>:3306/pingyangsite?character_set=utf8mb4"

# 种子管理员账号（首次部署时生效；部署完成后建议删除或修改）
SEED_ADMIN_PHONE=13800000000
SEED_ADMIN_PASSWORD=<强密码，勿用示例值>
```

**② `config/prod.env`**（API 运行时配置；复制自 `config/prod.env.example`）：

```bash
# 复制模板
cp /opt/app/pingyangsite/config/prod.env.example /opt/app/pingyangsite/config/prod.env
```

填写全部必填项（`<填写>` 占位符）。各变量含义见**附录 A**。要点：

- `SESSION_SECRET`：`openssl rand -hex 32` 生成；
- `REDIS_HOST=127.0.0.1`、`REDIS_PORT=6379`（模板中的 `REDIS_PASSWORD` 未接线，删掉即可，见附录 B）；
- `STORAGE_DRIVER=oss` + OSS 四要素（`OSS_REGION`/`OSS_BUCKET`/`OSS_ACCESS_KEY_ID`/`OSS_ACCESS_KEY_SECRET`）；
- `MT_MODE=real` + 阿里云机器翻译密钥两项；
- 模板中 `DB_*` 变量未接线（数据库连接以 ① 的 `DATABASE_URL` 为准），可删除该段避免误导。

**③ `frontend/site/.env.production`**（官网 Next.js 构建/运行时读取）：

```bash
# API 内网直连地址（Next 服务端 SSR/ISR/中间件预检使用，无需公网可达）
API_BASE_URL=http://127.0.0.1:3001
# 站点公开域名（含协议，不带尾斜杠；用于 SEO canonical / sitemap / robots）
SITE_URL=https://www.<域名>
```

> 后台 `frontend/admin` **无需环境变量**：运行时走同源相对路径 `/api/v1`，
> 由 Nginx 反代（`frontend/admin/src/api/http.ts` baseURL 为 `/api/v1`）。

## 5. 构建与进程管理（PM2）

### 5.1 启动顺序

**API 先行**（官网构建时会对静态可预渲染页做一次数据预取，API 就绪可让
预渲染拿到真实数据；未就绪也不阻断构建，页面回退运行时渲染）。

```bash
cd /opt/app/pingyangsite/services/api
npm run build
```

### 5.2 PM2 配置

创建 `/opt/app/pingyangsite/ecosystem.config.js`：

```js
module.exports = {
  apps: [
    {
      name: 'pingyang-api',
      cwd: '/opt/app/pingyangsite/services/api',
      script: 'dist/main.js',
      env: { NODE_ENV: 'production' },
      max_memory_restart: '512M',
      out_file: '/var/log/pingyang/api.log',
      error_file: '/var/log/pingyang/api-error.log',
    },
    {
      name: 'pingyang-site',
      cwd: '/opt/app/pingyangsite/frontend/site',
      script: 'node_modules/.bin/next',
      args: 'start -p 3000',
      env: { NODE_ENV: 'production' },
      max_memory_restart: '1G',
      out_file: '/var/log/pingyang/site.log',
      error_file: '/var/log/pingyang/site-error.log',
    },
  ],
};
```

```bash
sudo mkdir -p /var/log/pingyang && sudo chown $USER /var/log/pingyang
pm2 start /opt/app/pingyangsite/ecosystem.config.js
pm2 startup systemd -u $USER --hp $HOME   # 按提示执行输出的 sudo 命令
pm2 save
pm2 status    # pingyang-api / pingyang-site 均 online
```

### 5.3 官网构建与启动

```bash
cd /opt/app/pingyangsite/frontend/site
npm run build
pm2 restart pingyang-site
```

### 5.4 后台构建（纯静态）

```bash
cd /opt/app/pingyangsite/frontend/admin
npm run build          # 产物 dist/
```

### 5.5 构建内存说明

官网 `next build` 在 2C4G 机器上内存偏紧。若构建 OOM：

- 方案 A（推荐）：在开发机/CI 上执行 `npm run build`，将 `frontend/site/.next`
  与 `node_modules` 同步到服务器（rsync），再 `next start`；
- 方案 B：服务器加 swap：`sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`。

## 6. Nginx 配置

`/etc/nginx/conf.d/pingyang.conf`：

```nginx
# 上传大小上限对齐 API：图片 5MB、视频 2GB（upload.constants.ts）
client_max_body_size 2g;

server {
    listen 80;
    server_name www.<域名> <域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name www.<域名> <域名>;

    ssl_certificate     /etc/nginx/ssl/<域名>.pem;
    ssl_certificate_key /etc/nginx/ssl/<域名>.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;

    # 后台 SPA 静态资源（vite base=/admin/）
    location /admin/ {
        alias /opt/app/pingyangsite/frontend/admin/dist/;
        try_files $uri $uri/ /admin/index.html;
    }

    # API 同域反代（后台与官网前端相对路径 /api/v1 直连）
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 必修项：配合 API trust proxy 恢复真实客户端 IP（限流/登录锁定/IP 落库依赖）
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 官网（Next.js SSR/ISR）
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 8. 备份与监控

### 8.1 备份

- **RDS**：控制台开启自动备份（≥7 天，建议 14 天）；另加每日逻辑备份到 OSS：

```bash
# /etc/cron.d/pingyang-backup（每日 03:30 全库备份，保留 30 天）
30 3 * * * root mysqldump -h<RDS内网地址> -upingyang -p'<密码>' --single-transaction pingyangsite | gzip > /var/backups/pingyangsite-$(date +\%F).sql.gz && find /var/backups -name '*.sql.gz' -mtime +30 -delete
```

- **OSS**：Bucket 开启版本控制或生命周期（上传图片误删可恢复）。
- **代码**：GitHub 远程为权威备份；部署后打 tag：`git tag -a v1.2.0 -m "含 v1.2 上线"`。

### 8.2 监控与日志

- PM2 进程守护：`pm2 monit`、异常自动重启（已配 `max_memory_restart`）；
- 云监控：ECS CPU/内存/磁盘使用率、RDS 连接数与慢查询、OSS 用量告警；
- 应用日志：`/var/log/pingyang/*.log`（API 日志含审计：登录、上传、询盘提交）。

## 9. 常见问题排查

| 症状 | 排查 |
| --- | --- |
| API 启动即退出并报 `[config] …` | 缺环境变量：按报错信息补 `config/prod.env` 对应项 |
| 官网能开、后台接口 502 | Nginx `/api/` 反代目标或 API 未启动：`pm2 logs pingyang-api`、`curl http://127.0.0.1:3001/api/v1/health` |
| 上传失败 | OSS 四要素/子账号权限/Bucket 公共读；API 日志 |
| 询盘全部用户共用一个限流额度 | 必修项未做（trust proxy）：见附录 B |
| 后台白屏/刷新 404 | Nginx `/admin/` 的 `try_files` 未配置 |
| 官网内容后台改后不刷新 | 生产 ISR 60s 内生效属正常；超时未生效查 API/Redis 与 `pm2 logs pingyang-site` |
| 图片裂图 | OSS URL 是否公共读；CDN 域名解析 |
| 403 / 超时 | 安全组：RDS 白名单缺 ECS 内网 IP、ECS 未放行 443 |

## 附录 B：与开发计划的差异及部署前必修项

**B-1（差异）数据库使用 RDS 替代自建 MySQL 5.6.16**
开发计划 §10.2 原定自建库（因 RDS 无 5.6 在售）；现按公司已有资源使用 RDS
MySQL（建议 8.0）。数据模型已预留兼容（开发计划风险表 #8），上架后按 §7
冒烟全流程验证。

**B-2（差异/注意）Redis 密码变量未接线**
`config/prod.env.example` 中的 `REDIS_PASSWORD` 当前代码未读取
（`configuration.ts` 仅读 HOST/PORT）。生产 Redis 按 **本机部署、仅绑定
127.0.0.1、不设密码** 处理，由网络隔离兜底；若后续接入云 Redis 需先改造代码。

**B-3（部署前必修项）API 需启用 trust proxy**
当前 `services/api/src/main.ts` 未设置 `trust proxy`：经 Nginx 反代后，
`req.ip` 恒为 `127.0.0.1`，导致**询盘限流（同 IP 3 次/分）退化为全体用户共享
一个配额、登录锁定失效、询盘落库 IP 失真**。部署前须在 `bootstrap()` 中
`app.useLogger(logger)` 之后加一行（只信任本机 Nginx，不信任外部伪造头）：

```ts
// 仅信任本机反代（Nginx 同机部署）：恢复 X-Forwarded-For 中的真实客户端 IP
app.set('trust proxy', 'loopback');
```

> 与 §6 Nginx 的 `proxy_set_header X-Forwarded-For` 配套生效，二者缺一不可。
> 该改动须经负责人确认后合入（安全相关代码由开发者主导，CLAUDE.md §9）。
